## 公网 variable×stable 真机验收（2026-08-27，本机蜂窝/variable ↔ 腾讯云 stable）

本机切换到 variable NAT 网络（探测五端口映射不同），对端仍为公网机。
连续 6 轮 `real-wan.sh` 全部通过：双侧 punch connected（本机约 60~120ms、
对端约 100~120ms，含本机为 link0 与 link1 两种角色序），双向 ping 零丢包
（判定已锚定 ", 0"，杜绝 100% 误判），2MB 传输 MD5 一致，双侧 commit 的
socket ID 交叉一致（同一条路径）。

本轮串联暴露并修复四个缺陷（过程见提交链）：

1. 已建成的 link0 不再补发 OK——对端记关联晚于 commit 时的 OK 突发，
   link1 永远等不到（单侧建成）；
2. helper 信标在本侧建成即停发——对端 15s 预算内零握手来源，运营商
   NAT 随机分配端口下扫描打不中，PUNCH_TIMEOUT；改为本侧建成后继续
   播到预算耗尽，反向 PUNCH 不再限 link0；
3. **双侧路径分叉**（最隐蔽）：OK 补发曾从「收到 PUNCH 的 socket」发出，
   link1 在 helper Y 上建成而 link0 在 helper X 上互通——对称 NAT 下
   两条映射互不相通，隧道双向黑洞、60s 保活齐超时。补发固定走选定
   路径后收敛；
4. 验收脚本 ping 判定 `0(\.0)?% packet loss` 能命中 `100.0%` 的子串，
   黑洞链路被误判为通过，掩盖了 3。

实际建成路径为 helper 信标 + 反向握手 + OK 补发；Range 扫描作为备援
未成为关键路径（见下）。

## TUN 平台层假设复验（2026-08-27，对照实验）

背景：darwin 层「阻塞读 + 弃置 goroutine」设计的两个前提来自旧项目真机观察。
为排除「把自身代码问题记成操作系统设计」的可能，在当前工具链做双向对照
实验。环境：go1.26.6；macOS 15.6（darwin 24.6.0 arm64）；Debian 6.1.0-17
（amd64）。方法：utun 与 /dev/net/tun 各写对照程序，「非阻塞+poller」与
「阻塞裸 fd」两条路径 × 读/写/Close 三维；网络侧用 ping 打真实路由流量，
写路径以「手工构造 ICMP echo reply、ping 收到」判定端到端可用。

| 实验 | 结果 |
| --- | --- |
| macOS nb+poller 读 | ✅ 连读 5/5 包、SetReadDeadline 可用 |
| macOS nb+poller 写 | ✅ 手工 ICMP 回应被 ping 收到（端到端） |
| macOS 阻塞读 × Close | ❌ 4s 不醒（弃置语义的依据，Go 对非 poller 文件的文档化行为） |
| macOS nb+poller 读 × Close | ✅ 以 file already closed 唤醒 |
| macOS 地址残留（正常退出不清理 / SIGKILL） | 均无持久残留：地址路由随接口亚秒内消失（首见"残留"是内核异步拆除窗口） |
| Linux nb+poller 停泊读 × Close | ✅ 干净唤醒，优雅退出不卡 |
| Linux 阻塞 fd 直接 NewFile × Close | ❌ 停泊读 ≥2s 不归——即 wg.Wait 永久卡死，现行「先 SetNonblock 再 NewFile」必要性证实（Go 文档化行为，golang/go#22939） |
| Linux nb+poller 写 | ✅ 端到端可用 |

判定：

1. 「utun 非阻塞进 poller 后 kqueue 不投递事件（数据面全死）」——**当前
   环境推翻**，且无公开先例佐证；旧观察无法考证（环境差异或误归因）。
   darwin 维持阻塞从硬性技术约束降级为**保守选择**。
2. 「configd 地址残留、下次启动必冲突」——当前 macOS **不可复现**；显式
   清理保留的真实理由是进程内拆栈必要（弃置语义下 fd 不关）+ 跨版本保守。
3. Linux 侧断言全部证实，归属正确（poller 注册为 Go 文档化行为、/32 安装
   为标准路由语义）。
4. 附带发现：Linux 上 tun up 触发 IPv6 DAD 噪声包（48B），现有路径可消化。

## netns NAT 实验室验收（2026-08-29，Debian 双 NAT + macOS 服务端）

拓扑：client1 → natgw1(100.64.1.100) → inet(公网路由器) → natgw2 → client2，
全部为 Debian 192.168.31.105 内的 netns；服务端跑 macOS。复现：
`natlab.sh <本机IP> <debian_ssh> [A..E]`。画像探测判定全部正确
（stable 五端口全等 / variable 五端口互异 / variable×variable 即时
NAT_UNSUPPORTED）。nat 类型五档：

- stable = MASQUERADE：端口保留 → 端口受限锥
- variable = MASQUERADE --random-fully：逐流随机 → 对称
- slirp = slirp4netns（用户态）：端口级全锥、丢包不留痕
- natpf = test/natpf 自写（用户态）：EIM 保留端口 + 端口受限过滤
  （-filter 可调 port/addr/full）+ 丢包不留痕

| # | 组合（variable×stable） | 结果 | 说明 |
| --- | --- | --- | --- |
| A | conntrack×conntrack（stable×stable） | ✅ 尝试 5 次建成 | 双侧 punch connected，双向 ping 零丢包 |
| B | conntrack×conntrack（variable×stable） | ❌ 8/8 超时 | ~3 万扫描候选零命中；抓包+conntrack 逐步定位，见发现 2 |
| C | variable×variable | ✅ 即时拒绝 | NAT_UNSUPPORTED×8，与 worker 判定分支一致 |
| D | variable×slirp | ✅ 尝试 1 次建成 | 全锥：beacon 直通，扫描未上场，平凡情形 |
| E | variable×natpf | ✅ 尝试 1 次建成 | 端口受限：**信标全灭、扫描独苗**（"最难组合"），sweep 段命中 |

### 机制结论：conntrack 的「负记录」一个毒，两种症状

conntrack 对未匹配入站包：丢弃但**留记录**（reply 元组占住
`本端端口 → 该来源`），叠加**按流分配**端口的保留机制，产生：

1. **stable×stable 先到先得竞态**：对端 punch 先到 → 留记录 → 本端
   保留失败回退随机端口（抓包实证 40894→1048）→ 双向元组永不匹配，
   预算内死锁；先发先到则 2-6ms 建成。单次成功率 ~1/3，重试（换
   socket 重掷）收敛。响应措施已落地：`stable_timeout` 5s→2s 早离场，
   交服务器重连重掷。
2. **variable×stable 三级扫描自败**：beacon 入站留的记录恰占住
   `stable端口 → 洞端口` 的保留权，扫描包源端口被改写（33080→20821）
   后与洞不匹配 → 命中率恒为 0。**开洞的端口与可扫描的端口互斥**，
   时序调整无解（洞的准入端口 = 恰好被洞自己的 beacon 堵死的端口，
   换目标端口/换 socket/调延迟都只是平移矛盾）。

### pf 档对照：失效归因收口

stable 侧换成「不留痕」的用户态 NAT（EIM 保留端口），同一三级扫描代码：
D（全锥）平凡建成，beacon 直通、扫描未上场；**E（端口受限，与 conntrack
同严）beacon 全灭，扫描 sweep 段命中、一次建成**——05 设计的「最难组合」
（信标全灭、扫描独苗）真实成立。结论：三级扫描代码无错，失效 =
conntrack「按流分配 + 留负记录」叠加。适用域：stable 侧为无 NAT / EIM
型 / 严格但不留痕 NAT 时全部成立；仅双端均为 conntrack 系（OpenWrt/
安卓热点/多数 CPE）时不可用（08-27 真机蜂窝×云 6/6 不矛盾：stable 侧
是公网机）。

## 复现口径

- 局域网：`real-lan.sh <本机LAN_IP> <debian_ssh>`（含双侧建成、
  双向 8MB MD5、保活 70s 校验）
- 公网：`real-wan.sh <公网ssh> [端口基值]`（CONNECT 自动重试容忍
  出口 IP 轮换）
- NAT 实验室：`natlab.sh <本机LAN_IP> <debian_ssh> [A..E]`（netns
  双 NAT：A=stable×stable、B=variable×stable、C=variable×variable、
  D=variable×slirp 全锥、E=variable×natpf 端口受限；单次尝试失败自动
  重试至多 8 次；扫描观察日志与客户端日志归档 /tmp/gtun-natlab/<组合>/）

两脚本任一校验失败即非零退出。真机测试的环境事实与踩坑记录见本目录 `README.md`。
